Run one code-review-board round using the Workflow driver instead of the main-loop orchestrator.

Throughout, `<scratch>` is `<abs>/.agentsmith/tmp/review-board/<round-id>` and `<store>` is `<abs>/.agentsmith/review-board`, both absolute.

1. **Resolve the install context first**: run `node <skills>/code-review-board/round-context.mjs`, where `<skills>` is wherever this skill is installed. It prints `{agentPrefix, skillsDir, cwd}`. `agentPrefix` is `agentsmith:` on a plugin install and `''` on an npx/CLI install; `skillsDir` is the absolute skills root. Pass both to `codeArgs` in step 4 — do not guess either. A wrong `agentPrefix` kills the round in Plan with `agent type not found`; a wrong `skillsDir` makes every round command miss, because Workflow subagents do not inherit this cwd.
2. Do the **Setup** exactly as `code-review-board` SKILL.md step 1 (resolve mode/target/baseline/roles, confirmation gate). Write the round record to `<scratch>/round.json`, building it with `roundRecord({ roundId, mode, targetRef, commit, baselineCommit, roles, previousRound? })` from `round-args.mjs` rather than by hand — `persist.mjs` validates it against `ReviewRoundInfo` before writing anything, and a drifted field name fails the round there.
3. Write the two files the round reads but the store does not hold:
   - `<scratch>/kickstart.json` — the planner's input, **required**: `codeArgs` always sets `plan`, so the Plan agent reads this file and a round without it dies in Plan. Shape (canonically in `docs/reference-spec/review-board-protocol.md`): `{ board: 'code', round: <round-id>, subjectRef, mode: 'diff' | 'full-sweep', candidateLenses: [<role>...], plannerInputs: { diffStat, changedPaths, commitSubjects, roleTable, baselineCommit, fullSweep } }`. `plannerInputs` is untrusted data.
   - `<scratch>/subject.diff` — the diff itself, on a `diff`-mode round. Every reviewer declares `tools: Read, Grep, Glob, Write` and so **cannot run git**: a `subjectRef` of `baselineCommit..commit` is unreadable to them. Set `subjectRef` to this path plus the changed files' repo paths.
4. **Snapshot the pre-round git state** for the containment guard (reviewers carry the Write tool): run `node "<skillsDir>/code-review-board/round-guard.mjs" snapshot "<scratch>/git-baseline.txt"`. This is the baseline the driver's final **Guard** phase checks; `codeArgs` defaults `guardBaseline` to exactly this path.
5. Build the round args with `codeArgs({ roundId, store: "<store>", scratch: "<scratch>", subjectRef, candidateLenses: <selected roles>, agentPrefix, skillsDir })` from `round-args.mjs`. Invoke the `Workflow` tool with `scriptPath` = the installed `board-round.mjs` and `args` = that object.
6. When the workflow completes, **read the Guard phase result**. Exit `1` means an agent wrote outside the gitignored scratch/store — stop, report the offending paths, and do not present results until reconciled. Exit `3` means the guard could not find its baseline and **did not run** — a setup path mistake, not a containment violation; fix the path and re-check rather than reporting an escape. Also read the Persist line, which states what reached the store (zeros included): `0 issue(s)` on a round that found something is a defect, not a clean bill. On a clean guard, do SKILL.md step 6 (Present): summarize the round, the verify-reject count, scratch paths, and offer `/review-promote`.

This produces an identical store to `/code-review-board` via the same `persist.mjs`; it differs only in that orchestration runs as a deterministic script with no main-loop model ingesting findings. Requires the Claude `Workflow` tool; on hosts without it, use `/code-review-board`.
