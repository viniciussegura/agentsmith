# Project-dependent rule content

**Decision.** `#swe-docs-layout` is the first rule whose *content* depends on the consumer project, and the dependence is realized as a **post-render rewrite that self-selects on the tag**. `applyLayoutOverrides` (`src/docslayout.js`) returns its input unchanged unless the module text's first heading defines `#swe-docs-layout`; `bin/cli.js` maps every module text -- core and bundle alike -- through it at one site, before `buildOutputs` is called. Conditional rule *text* is not held in `src/`: it lives in the rule source between `<!-- agentsmith:external-note -->` markers, which the transform unwraps when at least one row is `external` and strips whole otherwise. `buildOutputs` keeps its signature and its pure contract, and gains no `overrides` parameter.

**Why.** The override has to flow through the map, because every owner rule cites the map instead of restating a path -- that is what makes a one-place remap reach every reader. Self-selecting on the tag rather than on a module path is what keeps it true: the rule can move between sections, or into an on-demand bundle, without silently dropping every override. Silent non-application is the failure this feature exists to remove, so the mechanism preventing it cannot itself depend on where the file happens to sit.

**Rejected.**

- **Templated rows in the rule source.** Every row would carry generator syntax that a rule reader, `#ai-instruction-review`, and the markdown conventions all have to understand, paid for by every project to serve the few that write a config.
- **An appended override table**, left below the default one. Two tables disagreeing about where a record lives is worse than either alone, and the reader has no way to know which one an agent will follow.
- **An override reaching the owner rules.** It would put a path back into the rules the single-source map exists to keep paths out of, reintroducing exactly the drift being removed.
- **A paragraph constant owned by `src/`**, quoted verbatim in a reference-spec document. That is two copies with neither in `instructions/`: text shipping as instructions in every `AGENTS.md` with an external row, invisible to a rule reader, to `#ai-instruction-review`, and to the rule module's own drift check.
- **Create-on-first-run**, which the originating future-work note proposed: `install` writing the config when it is absent. `install` writing a committed team-decision file nobody asked for is precisely the unrequested edit the plan-then-confirm design exists to avoid. The config is the user's to author; `install` reads it, warns when git reports it ignored, and never creates, prunes, or uninstalls it.

**Consequences.** The owner tags in the map's table are now a **public contract**. A consumer's `.agentsmith/docs-layout.yaml` keys on them, so renaming or removing a tag invalidates that project's config. Deny-by-default makes the result a loud `install` failure rather than a silent non-application, which is the best available outcome, not an excuse: it is still a breaking change for every consumer carrying that key. This repo ships no `CHANGELOG`, so such a change is announced in the PR body (`#git-pr`), and adding a row therefore starts with choosing a tag meant to last.

The map is the single source of truth for naming **patterns** only while placeholders are kept. A relocated path need not retain them, except on the three rows whose records something else resolves individually: `#swe-reference-spec` must keep `<name>`, `#swe-design-decisions` must keep `<decision-slug>`, and `#swe-epic` must keep `<slug>` -- the last for a different reason, being a directory per record with children the rule mandates, so a slug-free path collapses every epic into one directory. Dropping a placeholder on either remaining row is a project declaring a different naming pattern -- up to one file per record type -- which is its call to make, because nothing cites those records individually. The cost is that an owner rule's own prose can then read a little false: `#swe-technical-debts` speaks of a file per debt in a directory, which a relocation to a single placeholder-free file quietly contradicts.

**What would reopen it.** A second rule whose content becomes project-dependent. One rule justifies a self-selecting transform and one marker pair; two would make the case for a declared conditional-content contract any rule module can use, rather than a second special case built the same way.
